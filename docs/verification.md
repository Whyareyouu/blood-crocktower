## Воспроизведение

Из корня проекта, после установки зависимостей и настройки `.env`:

```powershell
docker compose up -d db
pnpm db:migrate
$env:TEST_DATABASE = '1'
pnpm check
Remove-Item Env:TEST_DATABASE
pnpm build:web
pnpm build:api
docker compose up --build -d --wait
pnpm smoke
docker compose down
```

Для выполненной локальной проверки использован отдельный временный кластер
PostgreSQL в игнорируемом `.cache/`, доступный только на `127.0.0.1:55432`.
Тесты создавали уникальные временные таблицы и удаляли только их через GORM.
Мигратор и API использовали тот же кластер; Next.js запускался из production
standalone с ресурсами `.next/static`, как в Dockerfile.
Все временные серверные процессы после проверки остановлены.

## Ограничения проверки

- Docker CLI/daemon и Docker Desktop в окружении отсутствуют. Проверена
  конфигурация standalone Compose, но контейнеры и образы не собирались
  и не запускались. В Compose используется PostgreSQL 17; локальная проверка
  выполнена на 18.6. CI содержит PostgreSQL 17 и отдельный запуск всего стека
  с той же smoke-проверкой; удалённый CI в этой работе не выполнялся.
- Sandbox запрещает локальные TCP-соединения и часть операций с симлинками
  pnpm/каталогами Next.js. Интеграционные тесты, установка по lockfile,
  production-сборка и HTTP smoke выполнены с разрешённым запуском вне sandbox.
- Русские названия и краткие описания в каталоге — переводы проекта, если
  явно не указано иное. Сверка состава и метаданных с официальным снимком
  автоматизирована; она не доказывает каждое поведение роли. Реализация
  движка и проверки способностей остаются задачами следующих этапов.
- Визуальные, мобильные и многопользовательские игровые сценарии в этот
  этап не входят. HTTP smoke не заменяет их.
