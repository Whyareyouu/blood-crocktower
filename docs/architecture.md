# Архитектура

## Границы

- `apps/web` — Next.js App Router, TypeScript, пользовательский интерфейс.
- `apps/api/cmd/api` — HTTP-сервер Go.
- `apps/api/cmd/migrate` — отдельный запуск миграций.
- `apps/api/internal/config` — проверка переменных окружения.
- `apps/api/internal/database` — PostgreSQL, GORM, журнал версий схемы.
- `apps/api/internal/auth` — аккаунты, Argon2id и непрозрачные сессии.
- `apps/api/internal/access` — единая политика прав комнат и приватных бесед.
- `apps/api/internal/httpapi` — HTTP, CSRF, ограничения запросов и WebSocket.
- `docs/openapi.yaml` — OpenAPI реализованной диагностики и проект операций следующих этапов.
- `docs/contracts/protocol.schema.json` — единый источник HTTP DTO и WebSocket v1.
- `apps/api/internal/contracts` и `apps/web/lib/contracts` — генерируемые транспортные типы.

Единственный владелец доступа к БД — Go-сервер. Next.js обращается к нему
по HTTP, а в следующих этапах клиент подключится по WebSocket. Прикладные
запросы и миграции выполняются исключительно через GORM. SQL-файлов нет.

Веб-клиент обращается к `/api/*` того же origin: Next.js проксирует запросы
на Go. `API_INTERNAL_URL` — серверная переменная, не публичная настройка
браузера. Адрес для rewrite фиксируется во время сборки; в Docker это
`http://api:8080`, при локальной разработке — `http://127.0.0.1:8080`.

## Текущий объём

Реализованы диагностика, миграции схемы 1 → 2, аккаунты, сессии PostgreSQL,
формы входа/регистрации, восстановление своего членства и защищённый
WebSocket с `ping`/`pong`. Подписки, управление комнатами, чаты и игровой
движок ещё не реализованы. Текущая политика прав используется WebSocket
перед каждой комнатной/приватной командой; прошедшие её команды следующих
этапов также отвергаются без выполнения и без `ack`.

`/health/live` проверяет процесс, `/health/ready` обращается к журналу миграций
через ORM и возвращает 503 при недоступности БД или неприменённой схеме.
Миграции идемпотентны; версия 2 создаёт аккаунты, хеши сессий, комнаты,
членство и состав приватных бесед. Веб-операции создания комнат и бесед
остаются задачами этапа 3. Восстановление членства по UserID проверено на
изолированных записях настоящей PostgreSQL.

## Следующие подсистемы

Управление комнатами и членством, сообщения, игровое ядро,
индивидуальные проекции, журнал команд, слепой арбитраж и голосования
добавляются по roadmap. Игровое ядро не зависит от HTTP или React.

Команды одной комнаты обрабатываются последовательно. Состояние и журнал
фиксируются одной транзакцией до уведомления клиентов. `requestId` обеспечивает
идемпотентность. Клиенты получают только разрешённые проекции, включая
собственные ревизии видимости; внутренние номера скрытых событий не выдаются.

## WebSocket — транспорт и дальнейший контракт

Реализован `/api/v1/ws` с обязательными cookie, точным `PUBLIC_ORIGIN`
и подпротоколом `blood.v1`. [Контракт v1](contracts/README.md)
определяет DTO и проверяемые примеры; в этапе 2 выполняется только `ping`.
Go- и TypeScript-типы проецируются из одной JSON Schema:

```json
{"version":1,"type":"ping","requestId":"123e4567-e89b-42d3-a456-426614174000","payload":{}}
```

Ответы: `ack`, `error`, `rooms.snapshot`, `room.snapshot`, `self.snapshot`,
`conversation.snapshot`, `pong`. Снимки содержат `viewRevision`, относящуюся
только к одному видимому потоку получателя. После переподключения выполняется
полная повторная подписка; внутренние номера журнала не передаются.
Неизвестные команды отвергаются. Сессия и Origin проверяются до upgrade,
полномочия — при каждой команде и отправке данных. Проект уже фиксирует
сообщения лобби и чатов; игровые действия добавляются вместе с игровым ядром.
Сообщения проверяет JSON Schema 2020-12 через готовую Go-библиотеку.
Встроенная копия схемы генерируется и проверяется вместе с типами.
Сессия проверяется перед upgrade, каждой командой и отправкой ответа.
Выход и замена сессии закрывают её соединения с 4401; срок и внешний отзыв
проверяются также раз в секунду. Подробнее о защите и её пределах —
в [отчёте этапа 2](verification-stage2.md).

## Секретность

Гримуар доступен только отдельному человеку-Рассказчику. Создатель-игрок
получает безопасные полномочия модератора. Нельзя передавать в браузер
скрытые роли, эффекты, ночные выборы или чужие переписки с расчётом на то,
что интерфейс их скроет. Диагностика и обычные логи не содержат паролей
подключения или игровых секретов.
