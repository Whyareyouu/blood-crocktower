# Сетевые контракты v1

Схемы подготовлены на этапе 1; на этапе 2 реализованы аккаунты и защищённый
WebSocket с `ping`/`pong`. В [OpenAPI](../openapi.yaml) у каждой операции есть
`x-implementation-status`: доступны 10 операций со статусом `implemented`,
включая диагностику и собственное членство `/users/me/rooms`.
Подписки и чаты ещё не исполняются: после проверки сессии и полномочий
сервер возвращает ошибку, без `ack`. Операции `planned` остаются этапом 3. Гримуар, игровые
действия, арбитраж и голосования получат отдельные схемы вместе с реализацией
этапов 4–8: универсального `game.action` с произвольным JSON сейчас нет.

## Источник типов и существующие решения

[protocol.schema.json](protocol.schema.json) — единый источник HTTP DTO,
клиентских команд и серверных событий, JSON Schema 2020-12. OpenAPI ссылается
на те же определения. Файл `openapi.yaml` записан JSON, который является
допустимым YAML 1.2: его одинаково читают инструменты OpenAPI и Node.js без
дополнительной YAML-библиотеки.

До реализации проверены существующие `httpapi/router.go`, страница Next.js,
зависимости и проект конверта в `architecture.md`: готовых DTO и транспорта
не было. Для схем использованы [OpenAPI 3.1](https://spec.openapis.org/oas/v3.1.0.html),
[JSON Schema 2020-12](https://json-schema.org/draft/2020-12/json-schema-core) и
готовый [Ajv 8](https://ajv.js.org/guide/getting-started.html) с
[ajv-formats](https://ajv.js.org/packages/ajv-formats.html) для RFC3339 date-time.
Свой валидатор JSON Schema не создаётся. Рассмотренный
[oapi-codegen](https://github.com/oapi-codegen/oapi-codegen) генерирует Go HTTP
обвязку; здесь требуется также TypeScript и отдельный протокол WebSocket, а
проект первоначально не содержал HTTP handlers. Поэтому небольшой локальный скрипт проецирует
только используемые формы DTO в два языка; неизвестную форму он отвергает.
Ограничения строк и чисел проверяет Ajv. Новых зависимостей клиента нет.

Проверки и обновление типов:

```powershell
pnpm generate:contracts
pnpm check:contracts
pnpm test:api
pnpm typecheck
```

Скрипт проверяет все определения Ajv, ссылки и статусы операций, структуру
OpenAPI по [официальной метасхеме](https://spec.openapis.org/oas/3.1/schema/2022-10-07),
положительные и отрицательные JSON-примеры, компиляцию TypeScript-примеров
и отсутствие расхождений с генерируемыми Go/TypeScript-файлами. Метасхема
сохранена как `openapi-3.1.schema.json` без изменения. При проверке её копии
четыре `$dynamicRef: #meta` привязаны к существующей статической цели
`#/$defs/schema`: вложенный dynamic anchor не разрешается Ajv в этом документе.
URI-форматы метасхемы остаются аннотациями; локальные ссылки проверяются явно,
а ограничения самих DTO — отдельно полным Ajv 2020. Go-тесты проверяют
round-trip примеров и фактические ответы диагностических HTTP handlers.

Типы не заменяют проверку входных данных. TypeScript не проверяет значения
во время исполнения; Go `encoding/json` не проверяет `const`, `enum`, длины,
обязательные поля или границы чисел. В реализованном транспорте действуют
серверная валидация, ограничение тела и отклонение неизвестных полей.
Наличие сгенерированного интерфейса не даёт права отправлять событие.

## REST

Префикс `/api/v1`. Сессия — cookie `blood_session`, `HttpOnly`, `SameSite=Strict`,
`Secure` при HTTPS. JSON сессии содержит пользователя и CSRF-токен, без
идентификатора сессии. Предварительный токен выдаёт `GET /auth/csrf` с привязкой
к cookie; после входа идентификатор сессии заменяется, а CSRF-токен связан с
новой сессией. Все изменяющие HTTP-запросы требуют `X-CSRF-Token` и проверки
Origin. Для входа и регистрации действует также ограничение частоты.

Изменяющие операции комнат и чатов требуют `Idempotency-Key` UUID. Область
ключа — пользователь + операция + ресурс. Та же команда с тем же телом
возвращает сохранённый результат, с другим телом — `conflict`. HTTP и WS
одной прикладной операции используют общий журнал дедупликации.
Сохранение состояния и результата происходит транзакционно до уведомления.
Срок хранения команд должен покрывать всю партию; очистка для активной партии
запрещена. Аутентификация выполняется до поиска ключа и возврата результата.

`RoomSummary` содержит сценарий, режим, создателя, вместимость, число игроков,
состояние и доступность входа. `RoomView` содержит только публичные сведения;
`travellerRole` — публично объявленная роль Странника. Обычная роль игрока
не является публичным полем. История приватных бесед доступна только их
участникам, в том числе после окончания партии. Список приватных бесед всегда
ограничен текущим пользователем. Сообщения выдаются страницами до 100 записей
с непрозрачным `cursor`; курсор не является номером внутреннего события.

Без сессии возвращается `unauthenticated`. Закрытый чужой ресурс и
несуществующий ресурс дают одинаковое `not_found`, без подробностей в сообщении.
`APIError.message` — безопасный русский текст, `code` — машинный код;
пароли, внутренние ошибки и скрытые обстоятельства в ответ не включаются.

## WebSocket

Будущий endpoint: `GET /api/v1/ws`, подпротокол `blood.v1`. До upgrade
проверяются cookie, точное соответствие Origin разрешённому origin и версия
подпротокола; cookie и секреты не помещаются в URL. Отсутствующая сессия даёт
401, запрещённый Origin — 403, неподдерживаемая версия — 426. Проверка
авторизации повторяется для каждой команды, подписки и отправки события;
отзыв сессии немедленно закрывает соединение.

Конверт клиентской команды:

```json
{"version":1,"type":"room.ready","requestId":"123e4567-e89b-42d3-a456-426614174000","payload":{"roomId":"room-1","ready":true}}
```

Разрешённые команды: `rooms.subscribe`, `room.subscribe`,
`conversation.subscribe`, `room.ready`, `room.seat`, `room.message.send`,
`conversation.message.send`, `ping`. `ClientMessage` в TypeScript —
дискриминируемое объединение, в Go — закрытый интерфейс конкретных DTO.
Произвольных `payload` и возможности подписки на Гримуар нет.

Ответы: `ack`, `error`, `rooms.snapshot`, `room.snapshot`, `self.snapshot`,
`conversation.snapshot`, `pong`. `ack` с исходным `requestId` подтверждает
успешную фиксацию команды; снимок является отдельным сообщением и может прийти
раньше `ack`. Ошибка команды содержит тот же `requestId`; ошибка конверта,
когда UUID разобрать нельзя, может не содержать `requestId`. На повторную
команду сервер возвращает тот же результат; новые побочные эффекты запрещены.
`requestId` обязателен даже для подписок и `ping`, но их результат не требует
постоянного хранения. Неизвестная команда не выполняется.

После подключения клиент заново посылает подписки. Каждая подписка выдаёт
полный снимок: каталог, публичное состояние комнаты, личное представление
или последнюю страницу одной разрешённой приватной беседы. При изменении
видимых данных отправляется новый полный снимок соответствующего потока.
Для первой версии delta/replay-протокола нет. Приватная подписка не даёт
подписку на остальные беседы. `self.snapshot` отправляется только субъекту
`userId`, и содержит показанную ему роль и информацию, разрешённую движком.

`viewRevision` — десятичная строка, чтобы не терять точность JavaScript.
Ревизия относится к получателю и одному потоку; она увеличивается только
при изменении видимого ему представления. Скрытые изменения не меняют ревизию
и не создают пустых уведомлений. Внутренние номера журнала не передаются.
Ревизии разных потоков и подключений не сравниваются. Первый снимок новой
подписки всегда заменяет локальное состояние; внутри подписки клиент
отбрасывает повторные/более старые снимки, сравнивая ревизии как целые числа.

Размер текстового кадра — максимум 64 КиБ до разбора JSON; бинарные сообщения
не принимаются, сообщения чата ограничены 2000 символами схемы. Пустой payload
— строго `{}`. Приложение посылает `ping` каждые 25 секунд; отсутствие `pong`
60 секунд вызывает переподключение. Повторное подключение: задержка с jitter
от 1 до 30 секунд, затем полная повторная подписка. Закрытия 1000 — штатное,
1008 — нарушение протокола/прав, 1009 — большой кадр, 1011 — внутренняя ошибка,
4401 — сессия окончена. При 4401 автоматический повтор прекращается до входа.
Эти политики должны быть проверены интеграционно при реализации транспорта.

## Граница секретности

Создатель комнаты не получает доступ к чужому `SelfView`, Гримуару, скрытым
эффектам или перепискам. Авторизация не определяется наличием кнопки или
переданным клиентом идентификатором. Отдельная проекция Рассказчика будет
введена на этапе ручного режима и доступна только назначенному человеку без
игровой роли. До этого Гримуар не входит ни в один DTO. Нельзя расширять
публичные модели через `additionalProperties` или передавать секреты для
последующего сокрытия интерфейсом. Обычные логи содержат код результата и
безопасный `requestId`, но не тела личных сообщений и не игровые секреты.
