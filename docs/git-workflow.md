# Gitflow и Conventional Commits

## Настройка клона

После установки зависимостей выполните `pnpm run setup` из корня репозитория.
Команда меняет только локальный `.git/config`: подключает `.githooks`, шаблон
`.gitmessage` и стандартные имена веток Gitflow. Глобальные настройки не меняются.
Отдельная установка расширения `git-flow` не требуется.

| Ветка | Откуда создаётся | Куда сливается |
| --- | --- | --- |
| `main` | постоянная | содержит выпуски |
| `develop` | постоянная | интеграция разработки |
| `feature/*` | `develop` | `develop` |
| `release/*` | `develop` | `main` и `develop` |
| `hotfix/*` | `main` | `main` и `develop` |

Работа над задачей:

```sh
git switch develop
git switch -c feature/room-list
# Изменения, проверки и git add нужных файлов
git commit -m "feat(lobby): добавить список комнат"
```

После проверки и согласования слияния:

```sh
git switch develop
git merge --no-ff feature/room-list -m "chore: слить ветку feature/room-list в develop"
```

Подготовка выпуска:

```sh
git switch develop
git switch -c release/1.0.0
# Проверки, документация и исправления выпуска
git switch main
git merge --no-ff release/1.0.0 -m "chore: подготовить выпуск 1.0.0"
git tag -a v1.0.0 -m "Выпуск 1.0.0"
git switch develop
git merge --no-ff release/1.0.0 -m "chore: вернуть изменения выпуска 1.0.0 в develop"
```

Экстренное исправление создаётся через `git switch -c hotfix/<имя> main`
и после проверки сливается в обе постоянные ветки с `--no-ff`.
Общая история не переписывается. Удалённый репозиторий, push и защита веток
настраиваются отдельно, когда появится remote.

## Сообщения коммитов

Используется [Conventional Commits 1.0.0](https://www.conventionalcommits.org/ru/v1.0.0/):

```text
<type>(<scope>): описание на русском языке

Объяснение изменения и причины на русском языке.

BREAKING CHANGE: описание несовместимого изменения на русском языке
Refs: #123
```

Типы: `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`,
`ci`, `chore`, `revert`. Scope необязателен. Заголовок — не длиннее 100 символов.
Служебные маркеры, идентификаторы, код, ссылки и технические обозначения
сохраняют исходное написание. Описательный текст заголовка, тела и footer
пишется на русском. Это относится и к merge-коммитам; стандартное английское
сообщение Git нужно заменять аргументом `-m`.

`commit-msg` запускает commitlint. Автоматическая проверка выявляет отсутствие
русского текста в описаниях, но не заменяет проверку смысла и языка человеком.
Проверка формата и её тесты также запускаются в CI.
