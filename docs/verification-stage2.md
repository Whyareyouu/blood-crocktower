# Проверка этапа 2: аккаунты и безопасность

Дата: **17 ноября 2026 года**. Реализованы регистрация, вход, выход,
восстановление сессии и собственного членства, единая серверная политика
прав, CSRF, ограничения запросов и защищённый транспорт WebSocket.
Создание комнат, чаты, выдача Гримуара и игровые действия остаются будущими
этапами. Проверки прав используют изолированные записи PostgreSQL.

## Поведение и защита

- Логин — 3–32 латинских символа, цифры, `_` и `-`; регистр не учитывается.
  Пароль — 12–128 символов Unicode. Argon2id: 64 МиБ, 3 прохода, 4 потока,
  случайная соль 16 байт. Проверку и формат PHC обеспечивает готовая библиотека.
  Для отсутствующего аккаунта выполняется сравнение с фиктивным хешем;
  неизвестный логин и неверный пароль имеют одинаковый ответ 401.
- Случайный токен сессии — 32 байта; в PostgreSQL хранится только его SHA-256.
  Cookie `blood_session`: HttpOnly, SameSite=Strict, Path=/, без Domain,
  срок 30 суток. `Secure` включается для HTTPS; публичный HTTP конфигурация
  отвергает. Локальный HTTP допустим только для localhost/loopback.
- Вход меняет токен и отзывает прежнюю сессию текущего устройства. Другие
  устройства сохраняют собственные сессии того же UserID. Выход удаляет
  текущую сессию в БД и cookie; перезапуск API не теряет действующие сессии.
- Перед входом `GET /api/v1/auth/csrf` выдаёт случайный токен и HttpOnly
  cookie `blood_csrf` на час. После входа CSRF — HMAC-SHA256 от токена
  текущей сессии с разделителем назначения. Изменяющие `/api/*` требуют
  `X-CSRF-Token`, а переданный Origin должен точно совпадать с `PUBLIC_ORIGIN`.
  Дополнительно работает стандартная защита Go по Fetch Metadata/Origin.
  Cross-origin CORS-доступ к аккаунту не выдаётся.
- HTTP ограничен по сетевому адресу: запас 120 запросов, восстановление
  2/с. Регистрация/вход: запас 10 на адрес с восстановлением 1/6 с и запас
  5 на логин с восстановлением 1/12 с. Одновременно считаются до двух хешей.
  Размер HTTP JSON — до 8 КиБ; неизвестные поля, несколько JSON-объектов
  и неподходящий Content-Type отвергаются. Внутренние ошибки не выдаются.
- WebSocket требует действующую cookie, точный Origin и `blood.v1`;
  параметры query запрещены. Каждая команда проверяется по общей JSON Schema
  и повторно авторизуется; перед ответом сессия проверяется ещё раз.
  Выход и замена токена закрывают соединения с 4401. Срок и внешний отзыв
  проверяются раз в секунду. Предел кадра — 64 КиБ, бинарные кадры запрещены,
  без команд соединение закрывается через 60 секунд. Ограничения: четыре
  соединения на аккаунт, 256 на процесс; команды — запас 20 и 5/с на аккаунт,
  подключения — запас 10 и 1/с. Остановка API закрывает WebSocket.
- Политика доступа читает членство из БД при каждой проверке. Участник
  получает только собственные комнаты и беседы, создатель управляет своей
  комнатой. Гримуар разрешён исключительно назначенному человеку-Рассказчику
  в ручном режиме при отсутствии игровой роли. Создатель-игрок и программный
  модератор не получают этого доступа. Чужая и отсутствующая беседа дают
  одинаковый запрет; после удаления членства доступ прекращается.

## Выполненные проверки

| Проверка | Результат |
| --- | --- |
| `pnpm check` | Проверки соглашений и каталога, схемы, линтер, TypeScript, Go-тесты без БД и `go vet` пройдены |
| `TEST_DATABASE=1` + `pnpm test:api` | Пройдены на настоящей отдельной PostgreSQL 18.6; временные таблицы удалены через GORM |
| Миграции | Идемпотентность, обновление схемы 1 → 2 без потери журнала, отклонение более новой схемы и отмена контекста |
| Аккаунты | Argon2id/соль, отсутствие сырого токена в БД, одновременная регистрация одного логина, два устройства, перезапуск сервиса, ротация, выход и истечение |
| HTTP | CSRF, другой/null Origin, чужой сессионный CSRF, строгий JSON, лимиты входа и HTTP, запрет поддельного X-Forwarded-For |
| Права | Участник, создатель, Рассказчик, играющий Рассказчик, программный режим, посторонний и бывший участник; приватная беседа недоступна создателю, пустые ID не расширяют GORM-запрос |
| WebSocket | Настоящий upgrade, cookie/Origin/подпротокол, ping/pong, строгая схема, перепроверка членства, отзыв при выходе, истечение молчащей сессии, бинарные/большие кадры, лимиты команд/соединений и закрытие при остановке |
| Сборки | `pnpm build:api`, `pnpm build:web` пройдены; production Next.js standalone запущен с `.next/static` |
| `pnpm smoke`, `pnpm smoke:auth` | Совместный запуск API → PostgreSQL и Next.js; через реальный proxy проверены регистрация, два устройства, восстановление, CSRF, Origin и выход |
| `TestWebSocketThroughProxy` | На собранном production-стеке проверены upgrade, ping/pong и отзыв 4401 через настоящий Next.js proxy |
| Браузер | Регистрация, обновление страницы с сохранением входа, выход, ошибка неверного пароля, повторный вход; фокус после входа переведён в заголовок аккаунта |

Для воспроизведения после настройки `.env`:

```powershell
pnpm db:migrate
$env:TEST_DATABASE = '1'
pnpm check
Remove-Item Env:TEST_DATABASE
pnpm build:api
pnpm build:web
# В отдельных терминалах: pnpm dev:api и pnpm dev:web
pnpm smoke
pnpm smoke:auth
$env:SMOKE_WEB_URL = 'http://localhost:3000'
node scripts/go.mjs test ./internal/httpapi -run TestWebSocketThroughProxy -count=1
Remove-Item Env:SMOKE_WEB_URL
```

## Ограничения и следующий этап

- `go test -race` в данном Windows-окружении недоступен: CGO выключен,
  C-компилятор не настроен. В CI уже задан `go test -race ./...` на Linux.
- Docker daemon недоступен; контейнеры не запускались. Локальная проверка
  использовала PostgreSQL 18.6, CI/Compose используют PostgreSQL 17.
- Локальные TCP-подключения и standalone-симлинки требуют запуска вне
  sandbox. Проверки БД, HTTP, WebSocket и production-сборка выполнены
  с разрешённым доступом. Удалённый CI в этой работе не запускался.
- Лимиты и реестр WebSocket локальны процессу; PostgreSQL хранит аккаунты,
  сессии и членство. Для нескольких экземпляров API нужен общий ограничитель.
  За Next.js адреса клиентов объединяются в адрес прокси: произвольный
  `X-Forwarded-For` не принимается за достоверный IP. Это безопасное
  ограничение для текущего локального стека; доверенные прокси потребуют
  отдельной настройки при размещении.
- WebSocket-подписки, готовность, рассадка и чаты проходят проверку доступа,
  затем получают ошибку о недоступности операции. Они не исполняются и не
  подтверждаются `ack`. Гримуар отсутствует в публичных DTO и ещё не выдаётся
  даже Рассказчику. Политика полномочий готова для будущих обработчиков.
- Восстановление комнат проверено на сохранённом членстве, созданном тестом
  через GORM. Пользовательское создание и присоединение остаются этапом 3.
- Полная проверка мобильного интерфейса и игровых сценариев относится к этапу 9.

Первичные документы зависимостей и обоснование повторного использования —
в [docs/dependencies.md](dependencies.md#аккаунты-и-безопасность--этап-2).
