# Roadmap: веб-версия «Крови на часовой башне»

Статус: первый и второй этапы реализованы и проверены локально; игровые
механики ещё не реализованы. Галочки ставятся только после проверки
соответствующего результата. Разработка ведётся по Gitflow; сообщения
коммитов — Conventional Commits с русскими описаниями.

## Целевой результат

Многопользовательская игра на русском языке: аккаунты, список комнат,
ожидание участников, полный состав базовой коробки и два режима ведения —
человек-Рассказчик либо программа с играющим модератором.

Стек: **Next.js + TypeScript → Go + WebSocket → GORM → PostgreSQL**.
Весь доступ к БД и миграции — исключительно через ORM.

Голосовое общение находится вне сайта. В приложении работают общий и приватные
текстовые чаты. ИИ-сервисы, дополнения и пользовательские сценарии в текущий
объём не входят.

- [x] Подготовить каталог всех ролей коробки, их способностей, ночного порядка, меток и исключений.
- [x] Создать таблицу соответствия: источник → требование → реализация → проверка.
- [x] Подготовить структуру клиента, сервера и инфраструктуры.
- [x] Описать REST API в OpenAPI и контракты WebSocket для Go и TypeScript.
- [x] Настроить PostgreSQL, миграции GORM, конфигурацию окружения и Docker Compose.
- [x] Зафиксировать версии зависимостей и русскоязычные сообщения коммитов.

**Критерий готовности:** клиент, сервер и БД запускаются вместе; структура
правил и сетевые контракты определены. Сырые SQL-запросы отсутствуют.

Проверено 17 ноября 2026 года: [99 карточек](docs/rules/catalog.json),
[таблица соответствия](docs/rules/traceability.md), общие схемы и типы Go/TypeScript,
миграции на настоящей PostgreSQL, production-сборки и совместный локальный запуск.
Конфигурация Compose проверена; запуск контейнеров недоступен без Docker daemon.
Русские названия в каталоге пока рабочие переводы проекта. Подробности и границы
проверок — в [отчёте](docs/verification.md). Контракты будущих HTTP-операций и
WebSocket не означают, что обработчики следующих этапов уже реализованы.

## Этап 2. Аккаунты и безопасность

- [x] Реализовать регистрацию, вход и выход по логину и паролю.
- [x] Использовать Argon2id для хранения паролей и защищённые HttpOnly cookie для сессий.
- [x] Реализовать восстановление пользовательской сессии после обновления страницы.
- [x] Проверять авторизацию каждой HTTP- и WebSocket-команды.
- [x] Добавить защиту изменяющих HTTP-запросов, проверку Origin WebSocket и ограничения частоты запросов.
- [x] Разделить полномочия участника, создателя комнаты и Рассказчика.

**Критерий готовности:** пользователь возвращается в аккаунт и свои комнаты
с другого устройства; посторонний не получает доступ к чужим действиям и данным.

Проверено 17 ноября 2026 года: регистрация, вход и выход в браузере,
восстановление после обновления, отдельные сессии двух устройств, сохранение
членства по аккаунту и восстановление после перезапуска сервиса. На настоящей
PostgreSQL проверены миграция 1 → 2, права комнат и приватных бесед, CSRF,
Origin, отзыв WebSocket и ограничения запросов. Создание комнат, чаты и
выдача Гримуара остаются следующими этапами; для проверки прав использованы
изолированные записи членства. Подробности — в [отчёте этапа 2](docs/verification-stage2.md).

## Этап 4. Игровое ядро и ручной режим

Первым полностью работающим набором становятся **«Тучи сгущаются»**.
Это промежуточный этап, а не сокращение итогового объёма.

- [ ] Реализовать серверное состояние партии и последовательную обработку команд.
- [ ] Разделить настоящую и показанную роль, сторону, публичное и фактическое состояние жизни.
- [ ] Реализовать подготовку, первую ночь, последующие ночи, рассвет, день, номинации, голосование, казнь и закат.
- [ ] Добавить смерти, посмертные голоса, опьянение, отравление, защиту и условия победы.
- [ ] Воспроизвести последовательный подсчёт голосов по кругу, пороги, равенство голосов и ограничения номинаций.
- [ ] Создать закрытый Гримуар для отдельного человека-Рассказчика без игровой роли.
- [ ] Реализовать все способности и взаимодействия набора «Тучи сгущаются».
- [ ] Сделать публичные заявления и действия для блефа доступными независимо от настоящей роли.

**Критерий готовности:** группа проходит полноценную партию «Туч сгущаются»
с человеком-Рассказчиком; секреты выдаются только предусмотренным правилами
получателям.

- [ ] Реализовать «Секты и Вистерии».

- [ ] Проверить немедленные срабатывания и цепочки последствий.

**Критерий готовности:** весь состав коробки доступен в ручном режиме;
для каждой роли есть проверки поведения и ссылки на источник.

## Этап 6. Программный Рассказчик и слепой арбитраж

- [ ] Добавить выбор режима ведения при создании комнаты.
- [ ] Автоматизировать подготовку, распределение ролей, порядок действий, эффекты и переходы фаз.
- [ ] Сохранять случайные решения, чтобы повторная обработка не меняла их произвольно.
- [ ] Выдать создателю обычную игровую роль и полномочия модератора без доступа к Гримуару.
- [ ] Добавить фиксацию значимых заявлений из внешнего голоса.
- [ ] Предоставить конструктор проверяемых вопросов и утверждений, дополненный свободным текстом.
- [ ] Реализовать безопасные предложения: разбор публичного события, предусмотренная поправка правила, повторная обработка шага и отмена ещё не разрешённой публичной заявки.
- [ ] Показывать общую трактовку или условный пример вместо реальных скрытых обстоятельств.
- [ ] Исключить подсказки о скрытых ролях через доступность действий, ошибки и результаты проверок.
- [ ] Сохранять исправления отдельными событиями; уже выданную информацию уточнять явно.

**Критерий готовности:** программа ведёт формализуемые механики, а создатель
помогает разрешать ситуации без получения чужих секретов.

**Обязательная граница:** непонятный вопрос не получает выдуманный ответ.
Если ситуацию нельзя разрешить движком, уточнением формулировки или безопасным
исправлением, партия сохраняется на паузе. Полная автономность для всех
свободных трактовок без человека и ИИ не обещается.

## Этап 7. Голосование за исправления

- [ ] Публиковать предложение модератора до применения исправления.
- [ ] Показывать описание и причину без скрытых подробностей.
- [ ] Допускать остальных участников с ролями, живых по публичному состоянию, включая Странников.
- [ ] Исключать создателя из голосования и расчёта порога.
- [ ] Сохранять отключившихся участников в числе голосующих.
- [ ] Фиксировать состав голосующих и приостанавливать продвижение партии.
- [ ] Принимать предложение при `ceil(N / 2)` голосов «за».
- [ ] Ограничить голосование 60 секундами; без достижения порога отклонять предложение.
- [ ] Запретить принятие предложения при отсутствии голосующих.
- [ ] Применять одобренное исправление однократно после повторной серверной проверки.
- [ ] Не расходовать посмертные голоса и не изменять ограничения игровых номинаций.

**Критерий готовности:** спорное исправление нельзя применить единолично.
При четырёх допущенных голосующих достаточно двух голосов, при пяти нужны три.

Техническая пауза и изменение времени обсуждения голосования не требуют.
В ручном режиме решения принимает назначенный Рассказчик.

- [ ] Не делать обязательный выбор за отключённого игрока.

**Критерий готовности:** потеря соединения или перезапуск не теряют партию,
